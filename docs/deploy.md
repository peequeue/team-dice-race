# Deploying Team Dice Race

Everything here is done in a web browser, plus GitHub Desktop to upload the files. Allow about 30 minutes the first time. After setup, every change is published automatically when it's pushed to GitHub.

You will create three secrets along the way. Keep them in a password manager:

| Name | What it is | Make one like this |
|---|---|---|
| Cron secret | Lets the hourly job trigger the 4pm reveal | 40+ random characters |
| Setup token | Used once to create your host link | 40+ random characters |
| Supabase access token | Lets GitHub publish the server functions | Generated by Supabase in step 4 |

A password manager's "generate password" button is fine for the first two (letters and numbers only).

---

## 1. Put the code on GitHub

Done: the code is at github.com/peequeue/team-dice-race (public, which keeps GitHub Pages free). It contains no names, questions or keys. Claude pushes changes there; you don't need GitHub Desktop.

## 2. Create the Supabase project

1. Sign up at supabase.com (free plan).
2. **New project**. Name: `team-dice-race`. Region: **Sydney**. Set a database password (save it, though you won't need it day to day). Under **Data access**: untick **Enable Data API**, leave **Grant API access to new tables automatically** unticked, and tick **Enable RLS on new tables automatically**. The game never uses the Data API.
3. Wait a minute or two for it to finish setting up.

## 3. Set up the database

1. In Supabase, open **SQL Editor** (left sidebar) and click **New query**.
2. Open `supabase/migrations/0001_init.sql` from the unzipped folder in a text editor, copy everything, paste it into the query box and click **Run**. You should see "Success. No rows returned".
3. Go to **Project Settings > Vault** (or search "Vault"), and add two secrets:
   - Name `project_url`, value `https://<your-project-ref>.supabase.co` (the project ref is the random string in your Supabase dashboard address, and on Project Settings > General).
   - Name `cron_secret`, value: your cron secret.
4. Back in **SQL Editor**, new query: paste all of `supabase/migrations/0002_cron.sql` and **Run**. This schedules the hourly check.

## 4. Connect GitHub to Supabase

1. In Supabase, click your avatar (top right) > **Account preferences > Access Tokens > Generate new token**. Name it `github`. Copy the token.
2. On GitHub, open your repo > **Settings > Secrets and variables > Actions**.
   - **Secrets** tab > **New repository secret**: name `SUPABASE_ACCESS_TOKEN`, value: the token.
   - **Variables** tab > **New repository variable**: name `SUPABASE_PROJECT_REF`, value: your project ref.

## 5. Server function settings

In Supabase: **Edge Functions > Secrets** (sometimes under Project Settings > Edge Functions). Add:

| Name | Value |
|---|---|
| `CRON_SECRET` | your cron secret (same as in the Vault) |
| `ADMIN_BOOTSTRAP_TOKEN` | your setup token |
| `ALLOWED_ORIGIN` | `https://peequeue.github.io` |

## 6. Turn on GitHub Pages

On GitHub: repo **Settings > Pages**. Under "Build and deployment", set **Source** to **GitHub Actions**.

## 7. Point the site at Supabase

1. In Supabase: **Project Settings > API**. Copy the **Project URL** and the **anon public** key.
2. On GitHub, open `web/config.js` in the repo and click the pencil icon to edit. Fill in:
   ```js
   functionsUrl: 'https://<your-project-ref>.supabase.co/functions/v1',
   anonKey: '<the anon public key>',
   ```
   The anon key is safe to publish. The database is locked so it can do nothing by itself.
3. Click **Commit changes**.

## 8. Publish

1. On GitHub, open the **Actions** tab. Two workflows run after any push:
   - **Test and publish site** runs the rules tests and publishes the site.
   - **Deploy server functions** publishes the three functions to Supabase. It only runs when function code changes, so the first time, open it and click **Run workflow**.
2. Wait for both to show green ticks (a couple of minutes).
3. In Supabase, **Edge Functions** should now list `resolve`, `play` and `admin`.

## 9. Become the host

1. Open `https://peequeue.github.io/team-dice-race/admin.html`.
2. Paste your setup token and click **Create host link**. **Bookmark the link it shows.** It only appears once. Anyone with this link is the host.
3. Open the host link.

## 10. Set up the pilot season

On the host page:
1. **Would You Rather:** paste your questions, one per line: `question | option A | option B | a or b`. Add questions.
2. **New season:** name it, pick the first game day, leave **Board squares** at 90, enter the eight nicknames and pick each player's avatar, then click **Create season**.
3. **Copy all eight player links straight away** and send each player theirs privately (Teams DM is fine). Links are only shown once. If one goes missing, use **New link** in the players table.
4. Press **Start season**.

Before 4pm each weekday, players open their link and press Roll. At 4pm the server rolls for everyone. The first person to open the page after 4pm triggers the reveal straight away; otherwise the hourly job does it within the hour.

## Day to day

- **After Christmas Eve, or on public holidays:** press **Pause** (or **End season**). Unpause when you're back. Paused days are skipped and nobody loses their streak.
- **Lost or leaked link:** **New link** for that player. The old one stops working.
- **Something looks stuck after 4pm:** press **Resolve due days now**.
- **End of season:** awards appear on the host page automatically. Press **Publish to players** when you're ready.

## Trying it without deploying

Open `web/index.html#demo` from the published site (or the demo link Claude shared). It runs the real rules in your browser against seven bots, with a Skip to 4pm button.
